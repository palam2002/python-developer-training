What is Object-Oriented Programming?

Object-Oriented Programming (OOP) is a programming paradigm that organizes software around objects, which combine data (attributes) and behavior (methods).

Instead of organizing a program entirely around functions, OOP models concepts as interacting objects.

For example, a banking application might contain:

Customer — stores customer information.
BankAccount — maintains a balance and handles deposits and withdrawals.
Transaction — records financial operations.


Advantages of OOps

Modularity: Each class has a defined responsibility.
Reusability: Existing classes can be reused or extended.
Maintainability: Changes can be localized.
Extensibility: New implementations can support existing interfaces.
Testability: Components can be tested independently.
Data integrity: Objects can control how their state changes.

3. Constructors and __init__()

3.1 What is a constructor?
In beginner Python discussions, __init__() is often called the constructor because it initializes a new object.

More precisely:

__new__() creates and returns an instance.
__init__() initializes the instance after it has been created.
For ordinary classes, you usually only need to define __init__().

4. Instance variables and class variables
Python classes can define variables associated with individual objects or shared at the class level.

4.1 Instance variables
An instance variable stores information associated with one particular instance.

They are commonly created using self inside __init__().

4.2 Class variables
A class variable is defined in the class body and is normally shared by instances that access it through the class.

Real-world example
For a library system:

Instance variable: The title of a particular book.
Instance variable: The number of copies of that book.
Class variable: A common library name.
Class variable: A class-wide counter, if intentionally maintained.
Use class variables only when shared state is genuinely appropriate.


5.Instance, class, and static methods
Python offers three commonly used method types.

5.1 Instance methods:

An instance method receives the current instance as its first argument, conventionally named self

5.2 Class methods:

A class method is declared using @classmethod and receives the class as its first argument, conventionally named cls.
Use it when an operation needs to work with the class itself, or when creating an alternative constructor.

5.3 Static methods
A static method is declared using @staticmethod. Python does not automatically pass either an instance or a class to it.

Use static methods for related utility operations that do not require implicit instance or class state.


6. self and cls

6.1 What is self
self is the conventional name for the first parameter of an instance method. It refers to the current instance on which the method is called.

It is not a reserved Python keyword, but using the convention makes code readable and consistent


6.2 What is cls?
cls is the conventional first parameter of a class method. It refers to the class through which the method was called.

This removes the reference previously held by person. It does not necessarily destroy the object because another reference might still point to it

6.Garbage collection
When an object is no longer reachable, Python can reclaim its memory.

In CPython, reference counting typically reclaims many objects promptly, while cyclic garbage collection handles unreachable reference cycles. Other Python implementations may manage memory differently.


7.the del statement
del obj removes the variable binding named obj. It does not directly guarantee that the object is destroyed at that exact moment.
If other references remain, the object can still be used.


8.The _del_() method
In some circumstances, the finalizer may run when the object's last reference is removed. However, timing and behavior can vary, especially with reference cycles, interpreter shutdown, and different Python implementations.

Best practice: Do not rely on __del__() for critical cleanup such as closing files, releasing locks, or completing transactions.
